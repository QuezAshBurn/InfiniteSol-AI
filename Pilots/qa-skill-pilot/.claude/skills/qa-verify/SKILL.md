---
name: qa-verify
description: Independently verify an approved InfiniteSol task on its exact candidate after developer testing. Use for QA handoff, required-approach verification and affected regression checks.
---

1. Verify the installed skill from its own folder using `python scripts/verify_manifest.py EXPECTED_SHA256`, with the expected manifest hash supplied by the PM. Record the version, manifest hash and source-pack fingerprint. Use a recorded verification from the current run if the operator performed this step. Block on missing or mismatched verification. Read [quality](references/GOAL-AND-QUALITY.md), [approved work](references/APPROVED-WORK.md), and [peer review](references/PEER-REVIEW.md).
2. Require a task ID, goal, criteria, required approach, current approved Markdown reference and validity, exact candidate, developer evidence and named author, peer and QA assignments where applicable. Confirm QA is separate from authorship. Apply the counterpart-runtime rule to peer review. Use the supplied evaluation time only for clearly labelled synthetic cases. For real work use actual verification time and the approved deadline's timezone or offset.
3. Trace every criterion to observed evidence of the goal, required steps, and affected or related workflows. Run applicable independent tests only within approved scope. Developer tests are an entry check. Record what was checked and what remains unrun. Discard affected stale evidence when the candidate changes. Base synthetic judgments only on the supplied facts and label them as tabletop evidence.
4. Return **PASS** only when approval and current evidence support all required checks. Return **RETURN FOR CORRECTION** for a verified defect, regression, or skipped required step the responsible owner can correct. Return **BLOCKED** for missing, stale, inconsistent or expired evidence, approval or environment. State the blocker or correction and what needs a rerun. If authorization is invalid, stop the affected verification.
5. Report the task ID, exact candidate, skill version and hash, verdict, evidence per criterion and next owner or decision. PM owns closure. Keep the existing peer, business acceptance and release ownership. Never change the candidate during QA.
