# Open-source-first projects with zero new spend

Use **$0 in new project cash spend** as the default ceiling. The Solution Architect must present a viable open-source-first design using resources InfiniteSol already has and is authorised to use. Include project-specific AI usage, development, testing, staging, production and maintenance. Record existing subscriptions, shared infrastructure, staff time and capacity separately so the CEO can see what the project consumes. State the currency, forecast period, estimated usage and what may become a later expense. The ceiling stays at $0 until the CEO records an approved change.

1. **Start with the existing stack and open-source alternatives.** Compare versions, upstream lifecycle, project fit, security, interoperability, effort and exit cost. Build around suitable open-source components and prefer an authorised local or existing self-hosted path if it meets the requirements. For each core dependency, record the upstream source, exact licence and version, intended use and distribution, and release or maintenance evidence. Refer unclear terms to the Legal role. Record required attribution, notices and other obligations as applicable. Existing paid or proprietary tools may be reused within their approved allowance only when disclosed, when they add no project spend, and when an open-source option was considered. Any material change to an agreed open-source constraint needs a recorded CEO decision.
2. **Proof by environment and operating need.** Use `starter/templates/cost-plan.md`. Account for compute, storage, network, domains, third-party APIs, builds and AI usage, backups, monitoring, recovery and ongoing operations where applicable. Confirm existing capacity and service permissions. Show usable **Development, Testing, Staging and Production** separately. Local testing or a no-cost prototype provides evidence only for that scope. Before build, Finance independently checks the estimate and its assumptions. Before release, the Deployment Engineer and Finance reconfirm actual provisioning, billed usage and operating headroom. Keep required isolation, security, data protection, performance, recovery and QA gates.
3. **Verify zero-charge controls before relying on a hosted free tier.** Use current official terms and actual account configuration where available. Record quota, expiration, usage forecasts, capacity at the agreed peak and what happens when usage exceeds the allowance. Require a demonstrated no-charge stop or another verified basis that excess usage cannot create a charge. An alert, a credit, an expiring trial or the word “free” alone is insufficient. Avoid configurations with automatic overages or billable upgrades. Include the stop signal, who acts, and a fallback to stay within approved scope. Route work that would create any spend through the PM to the CEO before commitment or execution.
4. **Report the exact feasible scope.** Mark each environment and operating capability as feasible with evidence, unverified, or blocked. If the full scope cannot fit the ceiling, show what a reduced or deferred scope can deliver, and give the cheapest evidenced compliant option with a budget decision request when needed. Stay within the currently approved scope until an authorised decision changes it. Update the plan when requirements, deployment configuration, vendor terms, expected load or recurring obligations materially change. For a service already live, record the cost risk promptly and follow its approved incident and maintenance procedures.
