name: implement-approved-story
description: Implement a scoped InfiniteSol story after the PM dispatches its exact approved revision. Use for the assigned author's development and developer-test handoff before independent review.
---

1. Verify the installed package with `python scripts/verify_manifest.py EXPECTED_SHA256` or use the operator's same-run verification. Record its version, hash and source pack. Read [approved work](references/APPROVED-WORK.md), [engineering standards](references/ENGINEERING-STANDARDS.md), [goal and quality](references/GOAL-AND-QUALITY.md) and [peer review](references/PEER-REVIEW.md).
2. Verify current written authorization and PM dispatch for the exact task, story revision, actor, allowed paths, required approach, time and spend. Record the baseline and preserve existing changes. Return BLOCKED before edits if approval, baseline or other prerequisites are missing, changed or inconsistent. Return READY TO IMPLEMENT for a valid simulated readiness check without doing project work.
3. Inspect relevant callers, contracts, tests and affected behaviour. Implement the smallest complete change within scope. Capture the required baseline and preserve existing behaviour. Route unresolved business rules to the BA and scope decisions to the PM. Stop affected work on scope, budget or permission gaps.
4. Execute applicable developer tests, build and code checks and record instructions, actual outputs, command exit status, candidate identity and any missing checks. Include a regression test and verify issue evidence on the baseline when applicable. Return RETURN FOR CORRECTION if a required check fails and the author can address it. Recheck the exact corrected candidate before handoff. Return BLOCKED when evidence or the environment cannot be obtained.
5. Return READY FOR PEER REVIEW only after the developer checks and required change record are current. Include task and acceptance IDs, baseline, candidate or artifact digest, diff, author role and runtime/session, affected documents, actual tests, known limitations and independent peer and QA handoff. Keep independent review, QA, PM closure and release approvals with their existing owners. Do not send, merge, deploy or spend without the applicable authority.
