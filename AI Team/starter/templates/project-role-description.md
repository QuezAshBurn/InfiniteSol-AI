# Project role description

The Solution Architect writes this description with the relevant specialist and BA. Store it under `Projects/<Project Name>/docs/roles/`. The PM records the approval and uses the exact version when assigning the role. Refer to `AI Team/ROLE-CATALOG.md` from the company root for company-wide responsibilities. Link the assigned company role prompt in the project copy.

| Field | Project-specific details |
|---|---|
| Project and role | Project ID, role name, company role ID and prompt reference. One approved role description may require multiple capabilities. |
| Document control | Owner, revision, date, status, approval record and review trigger. |
| Assignment purpose | Why the role is needed for this project, the phase and when its work starts. Link the approved goals and deliverables. |
| Industry competence | Required workflows, terminology, business rules and relevant jurisdiction or domain constraints. Cite the controlling sources. |
| Technical competence | Exact languages, platforms, interfaces, tools and versions. Specify proficiency for the relevant development, integration or verification tasks. |
| Evidence of readiness | Relevant reviewed work or an authorised practical check, expected result, reviewer and recorded outcome. |
| Responsibilities and limits | Owned work, decisions the role can make, approvals it must obtain, and what it hands off. Record access, data and environment limits. |
| Development skill requirements | Link the exact approved project bundle and revision in `../project-skills.md` when required. |
| Outputs and acceptance | Artifacts, affected documentation, observable completion criteria, test or review evidence and independent verification owner. |
| Handoffs and escalation | Inputs from other roles, who receives each deliverable, and when to stop and escalate to the PM. |

For example, a senior full-stack developer assigned to a Python API might need the project's approved Python version, API framework, database client, authentication rules and contract test tools. Record the exact stack and evidence for the actual project. Keep the author's developer checks, independent peer review and QA verification distinct.
