# Project memory

**Project:** Record the project ID and name.  
**Owner:** Project Manager. The Technical Writer maintains the index.  
**Requirements baseline:** Record the exact business requirements file and revision, approving decision and approved scope.  
**Status and revision:** Record the revision and date. Link the project record and approved scope from the project copy.

Set up this memory when the PM has recorded approval of the owning project's business requirements baseline. Store only this project's requirements-derived rules, tenant variations, and regulatory decisions or open applicability questions. Link each entry to the applicable requirement or approved project decision, with its exact revision and scope. Use the source records for approval authority. Entries apply only to the project ID above.

| Record | Content | Responsible owner |
|---|---|---|
| [Project rules](project-rules.md) | Approved business logic, technical invariants and project constraints, with pending details marked as open. | Business Analyst and relevant specialist |
| [Tenant rules](tenant-rules.md) | Tenant-specific configurations and explicit overrides that the project permits. | Business Analyst and designated tenant owner |
| [Regulatory register](regulatory-register.md) | Jurisdiction, applicable provisions, affected requirements, qualified review and evidence. | Legal Research and Drafting Agent and qualified reviewer |

Read the approved task first, then the owning project's applicable entries and their source records. Use a rule only when the source revision, scope and approval are current. Report unresolved source conflicts or missing approvals to the PM and pause affected work. Reassess affected entries after an approved requirements change. Record changes to rules, assumptions, decisions or applicable regulations, preserve superseded versions, and update the project document register. Use redacted or synthetic examples and keep credentials and raw customer data outside memory. Restrict tenant context to the authorised project and tenant. Any future MCP connection or RAG index requires its own approved scope.
