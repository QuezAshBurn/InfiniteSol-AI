Assign `REQ-0001` format IDs to incoming requests, `P-0001` format IDs to classified projects, and project-scoped change IDs to changes. Retain the intake row after linking it to a project or change. Use a separate directory for each project.

## Current approved build slot

- Project ID, scope and budget decision ID
- Assigned developer pair and current feature owners
- Runtime assignments by change: author and reviewer. Use one Codex and one Claude Code session. Record the required counterpart runtime, independent identity and authority for any substitute reviewer.
- Current review backlog and next checkpoint
- Next proposed priority shift and effect, if relevant

## Critical alerts and PM fallback

- CEO-approved primary route and backup route (method and authorised destination reference)
- Named operator when the PM is unavailable and how the operator is contacted
- Delivery acknowledgement method, response checkpoint and where the alert record lives
- Synthetic rehearsal date, outcome, evidence reference and resolution of any gaps
- If delivery is unavailable, record `PENDING OPERATOR`, the failed route and the next checkpoint

### Critical-incident pause authority

- CEO decision, approved Markdown path and exact revision, effective period, allowed scope and qualifying threshold
- PM and named backup, maximum pause duration, notification and fallback route, restart authority and conditions
- Incident, observed qualifying evidence, build checkpoint, pause and escalation times, notification evidence, and recorded restart decision

## Readiness rehearsal

- Approved work authorization, scenario and synthetic data, participants, dates, expected and actual actions, evidence and disposition
- Real signatory, billing, support owner, backup and operator checks applicable to the commitment or launch
- Blocking gaps, owners, readiness decision and next verification date
